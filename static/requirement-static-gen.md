# 需求文档：博客静态站点生成与自动部署

## 背景与目标
为博客增加一键生成纯静态站点的能力，支持增量生成、自动化部署到 GitHub Pages 或 OSS，以及评论系统的静态适配。目标是将动态博客无缝转换为可托管在静态服务器上的版本，减少服务器依赖。

## 功能需求
1. **静态站点生成**
    - 后台新增“生成静态站点”功能，管理员触发后，将当前所有已发布文章、分类页、标签页、归档页、首页（含分页）预渲染为纯 HTML 文件。
    - 保持与动态站点一致的页面样式、目录导航、代码高亮、图表（ECharts 可转为静态图片或保留 JS）。
    - 生成结果打包为 ZIP 下载，或直接输出到指定本地目录。

2. **增量生成**
    - 首次全量生成后，后续仅重建发生变化的文章及其相关联的页面（首页、分类页、标签页）。
    - 检测文章新增、修改、删除事件，精确更新受影响的 HTML 文件。

3. **自动部署**
    - 支持配置部署目标：GitHub Pages（提供 Token 和仓库名）或阿里云 OSS 静态网站托管。
    - 文章发布时可勾选“自动部署”，发布成功后自动触发生成和推送流程。
    - 提供部署日志页面，展示每次生成的状态、耗时、错误信息和最终访问 URL。

4. **评论系统适配**
    - 后台博客设置增加“静态站点评论提供商”选项：Giscus、Waline 或无。
    - 根据选择，生成的静态页面中自动嵌入对应评论组件的初始化代码，并传入必要配置（如 repo、appId 等）。
    - 确保评论框在静态页面中正常加载，访客可参与互动。

## 验收标准
- 后台点击“生成静态站点”，数分钟内得到完整静态文件目录。使用 `npx serve` 本地启动后，可正常浏览首页、文章、分类、标签、归档，所有链接跳转正确，样式与动态站点一致。
- 修改一篇文章标题后再次生成，只重建该文章页和首页，其他页面未变动。
- 配置 GitHub Token 和仓库后，生成完成自动推送至 `gh-pages` 分支，2 分钟内通过 `username.github.io` 看到更新内容。
- 在博客设置中选择 Giscus，填写参数后重新生成，静态文章页底部出现可用的 Giscus 评论框；切换为 Waline 再次生成，评论组件正确替换。
- 部署日志页可看到每次生成和推送的详细记录。
