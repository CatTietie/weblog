# 需求文档：多站点多租户 SaaS 化改造

## 背景与目标
将现有单站点博客系统升级为多租户架构，使得单一部署实例可同时服务多个独立博客站点。每个租户拥有完全隔离的数据和功能，租户间不可见。需支持基于域名的前台租户识别，以及基于登录用户的管理端租户限定。需新增超级管理员界面管理所有租户。

## 功能需求
1. **数据隔离**
    - 在所有核心业务表（文章、分类、标签、评论、用户、博客设置、通知、简历等）中添加 `tenant_id` 字段。
    - 实现 MyBatis-Plus 拦截器或 AOP 切面，在数据访问层自动注入当前租户 ID，确保 CRUD 操作限定在租户范围内。
    - 已存在的默认数据可归属到默认租户（如 `tenant_id = 0`），兼容历史数据。

2. **租户识别**
    - 管理端：从登录用户的 JWT 或关联信息中获取所属租户，限制其只能操作自己租户的数据。
    - 公开前台：根据请求的 Host 头匹配数据库中的租户域名配置，自动加载对应站点的博客名称、Logo、文章列表等。
    - 超级管理员可通过 `/admin` 前缀的统一入口登录，切换管理不同租户（或拥有全局视图）。

3. **超级管理员功能**
    - 新增租户管理页面：创建租户（配置名称、域名、管理员账号）、启用/禁用租户、编辑租户配置。
    - 超级管理员可查看所有租户列表，并进入指定租户的后台进行管理操作。

4. **文件与资源隔离**
    - 阿里云 OSS 上传路径按租户隔离（如 `/tenant_xxx/images/`）。
    - 文件管理页面只显示当前租户上传的文件。

5. **WebSocket 通知隔离**
    - 评论回复等实时通知仅推送给同租户的用户，跨租户不可见。
    - 全局通知按租户独立发送。

6. **兼容性保证**
    - 现有所有功能（搜索、仪表盘统计、简历模块、评论审核等）均需在租户隔离下正常运行。
    - 确保单租户部署（无 tenant_id 意识）升级到多租户时数据不丢失。

## 验收标准
- 创建两个租户 A 和 B，分别绑定域名 `a.blog.com` 和 `b.blog.com`。租户 A 发布 3 篇文章，租户 B 发布 2 篇。
- 访问 `a.blog.com`，首页仅显示 A 的 3 篇文章，博客名称和 Logo 为 A 配置；访问 `b.blog.com` 同理。
- 租户 A 管理员登录后台，文章列表仅显示 A 的文章，尝试通过修改接口参数获取 B 的文章 ID 返回无权限或 404。
- 租户 A 上传图片，租户 B 文件管理页中不出现该图片。
- 租户 A 文章下发生评论回复，租户 B 用户的 WebSocket 通知铃铛无变化。
- 超级管理员可查看全部租户，禁用租户 B 后，`b.blog.com` 返回站点不可用提示。
