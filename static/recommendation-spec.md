# 智能内容推荐与用户画像系统需求文档

## 1. 项目背景与目标
当前 Weblog 博客系统已经积累了可观的用户量和文章资源，但首页及详情页的信息呈现完全由发布时间决定，缺乏个性化引导，导致内容曝光不均、用户留存偏低。本需求旨在为 Weblog 新增智能内容推荐与用户画像模块，在不侵入现有业务逻辑的前提下，通过无感行为采集、兴趣建模、混合推荐算法以及运营配置工具，实现“千人千面”的内容分发。

## 2. 已有系统约束与依赖
本模块需要深度整合 Weblog 已有的以下能力和规范：
- 用户认证体系：基于 JWT 的登录态，用户角色分为普通用户、作者、管理员。
- 文章管理模块：文章拥有唯一 ID、标题、正文、标签（多对多）、分类、发布时间、作者等字段。
- 系统框架：前端为 React + Ant Design，后端 API 遵循 RESTful 风格，数据库为 PostgreSQL。
- 现有的全局统计：文章阅读量、点赞量等基础热度数据每日更新。
- 系统部署结构：前端静态资源托管，后端服务容器化，配置通过 ConfigMap 下发。

## 3. 功能需求

### 3.1 用户行为采集与偏好建模
在前台所有公开页面（首页、文章详情、标签页、搜索结果页、用户主页等）进行无侵入式埋点，采集以下行为：
- 文章阅读时长：页面停留超过 5 秒开始计时，每 10 秒上报一次心跳，离开页面时汇总总时长。
- 标签点击：用户点击文章详情页或标签云中的任意标签。
- 搜索关键词：用户在搜索框提交的检索词。
- 简历查看（若存在）：点击“关于作者”或简历页面的行为。
- 滚动深度和交互：可选，作为辅助信号。

采集到的行为日志以 JSON 格式异步发送至 `/api/analytics/events`，后端暂存于行为日志表。每天凌晨 2:00 执行离线批处理任务，为每个登录用户生成/更新兴趣标签权重数组，算法要求：
- 阅读时长按分钟衰减加权（例如每完整阅读 1 分钟记 1 分），不同行为赋予不同基础分（搜索 3 分，标签点击 2 分，简历查看 1 分）。
- 采用时间衰减因子（半衰期 7 天），使近期行为影响大于远期行为。
- 权重数组存储为 JSON 对象，如 `{"Spring Boot": 15.2, "Vue": 8.7}`，值归一化到 [0,100]。
- 未登录用户不生成持久化画像，仅使用会话内临时统计或全局默认推荐。

同时，提供后台管理界面，管理员可以查看任一用户的兴趣分布饼图、原始行为日志明细，并支持手动修正权重数值（添加、删除、调整某标签权重），修正后画像立即生效。

### 3.2 推荐算法实现与前端呈现
实现一个统一的推荐接口 `GET /api/recommendations/posts`，接受查询参数 `limit`（默认10），根据用户身份返回个性化文章列表。
- 对于已登录且有历史画像的用户：采用基于内容的推荐，计算用户兴趣标签权重与文章标签的匹配度（余弦相似度），结合文章热度（阅读量、点赞量归一化）和发布时间衰减，加权排序。
- 对于新用户或无画像用户（冷启动）：返回 5 篇最近一周内发布的热门文章（按阅读量排序）+ 5 篇编辑精选文章（由后台手动标记），混合时随机交错排列，确保前端展示多样性。
- 推荐结果中必须去重，不包含当前浏览的文章（如从详情页请求），且同一作者的文章最多出现 3 篇。

前端改动：
- 在首页原有文章列表的最顶部插入一个“为你推荐”横滑板块（移动端可左右滑动），展示 6 篇文章的封面卡，数据来自推荐接口。
- 在文章详情页，将原有“最新文章”侧边栏替换为“相关推荐”，内容基于当前文章的标签和内容相似度从推荐接口的备选集中筛选，确保高度相关且不包含当前文章。
- 所有推荐卡片均需包含文章标题、摘要、标签、阅读量、点赞数，点击直接跳转。

### 3.3 推荐效果统计与运营配置
后台仪表盘新增“推荐效果”看板，展示以下核心指标（默认展示过去 7 天，可切换时间范围）：
- 推荐模块点击率（CTR）：推荐卡片点击数 / 推荐模块曝光次数。
- 推荐结果人均点击篇数。
- 推荐文章池与全站平均热度对比曲线。
- 按标签维度的推荐效率分析。

运营配置页面提供以下能力，所有配置修改后需在 10 分钟内生效（通过缓存失效或动态拉取）：
- **强制置顶**：选择一篇文章，使其在目标用户群的推荐流中始终排在首位，可设定生效用户群体（全部、拥有特定标签的用户、指定用户）。
- **标签屏蔽**：全局或针对特定用户群屏蔽某些标签，这些标签对应的文章永不进入推荐流，即使与用户兴趣匹配。
- **手动调整文章推荐权重**：对特定文章设置权重乘数（0.5~5.0），与算法得分相乘，用于推广优质旧文或降低低质内容曝光。
- **编辑精选管理**：标记/取消编辑精选文章，直接影响冷启动推荐池。

## 4. 数据模型概要
在现有数据库基础上新增以下表：

**user_profile**
- user_id (bigint, FK to users)
- tag_weights (jsonb)  -- 兴趣权重
- updated_at (timestamp)

**behavior_log**
- id (bigserial)
- user_id (bigint, nullable)
- session_id (varchar)
- event_type (varchar)  -- read, tag_click, search, profile_view
- target_id (varchar)   -- 文章ID、标签名或搜索词
- payload (jsonb)       -- 时长、滚动深度等
- created_at (timestamp)

**recommendation_config**
- id (serial)
- key (varchar) unique  -- 如 'top_pinned', 'blocked_tags'
- value (jsonb)
- updated_at (timestamp)

**editor_pick**
- article_id (bigint, FK to articles)
- order (int)
- created_at (timestamp)

**recommendation_log**
- id (bigserial)
- user_id (bigint)
- context (varchar)  -- home, article_sidebar
- served_articles (jsonb)  -- 推荐的ID列表
- clicked_id (bigint, nullable)
- created_at (timestamp)

## 5. 接口约定（非正式）
- `POST /api/analytics/events`  接收前端埋点数据
- `GET /api/admin/users/{id}/profile`  管理员查看用户画像
- `PUT /api/admin/users/{id}/profile`  管理员修改兴趣权重
- `GET /api/recommendations/posts?limit=10&context=home`  个性化推荐
- `GET /api/admin/recommendations/metrics?start=&end=`  效果数据
- `GET /api/admin/recommendations/config`  获取配置
- `PUT /api/admin/recommendations/config`  更新配置

## 6. 验收标准
1. 用户连续阅读 3 篇标签含“Spring Boot”的文章后，次日凌晨批处理结束后，其兴趣画像中“Spring Boot”权重明显大于其他标签，管理员后台饼图可验证，且能看到原始行为日志。
2. 该用户登录后访问首页，“为你推荐”横滑板块展示的文章中至少 80% 标签包含“Spring Boot”或相关技术栈。
3. 点击任一推荐文章进入详情页，右侧“相关推荐”列表中的文章与当前文章标签重合度高于 60%，且不出现当前文章本身。
4. 未登录用户或首次登录无行为的用户，首页推荐板块显示的文章为近一周热门与编辑精选各 5 篇的混合。
5. 管理员在后台将一篇发布较早的文章推荐权重调至最大值（5.0）后，标签匹配该文的用户在 10 分钟内刷新首页，该文排在推荐流首位。
6. 管理员屏蔽标签“Java”后，一位主要兴趣为“Java”的用户登录，推荐流中不再出现任何带有“Java”标签的文章，但依然会出现“Spring Boot”（假设未同时屏蔽）。
7. 推荐效果看板能够准确展示前一天的点击率数据，且与 recommendation_log 表记录吻合。
