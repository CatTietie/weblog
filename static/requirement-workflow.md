# 需求文档：博客自动化工作流引擎

## 背景与目标
为博客系统植入一个可编排的自动化规则引擎，让管理员通过可视化拖拽定义“事件触发 → 条件判断 → 执行动作”的自动化流程，减少重复人工操作，并支持与外部系统集成。

## 功能需求
1. **规则定义与存储**
    - 提供可视化流程编辑器，支持拖拽节点：触发器（文章发布、新评论、新用户注册）、条件节点（字段比较、关键词包含等）、延时节点（等待固定时间）、动作节点（发送邮件、调用 Webhook、站内通知）。
    - 节点间通过连线组成流程，支持条件分支（是/否路径）。
    - 流程保存为 JSON 结构存储到数据库，后端可解析执行。

2. **规则引擎执行**
    - 后端监听业务事件，匹配所有关联规则，实例化流程并顺序执行各节点。
    - 条件节点评估表达式（如“文章分类 == 公告”），决定后续走向。
    - 延时节点使用任务队列或定时器异步等待后继续执行后续节点。
    - 执行过程中捕获异常并记录，不影响其他规则和主业务。

3. **动作实现**
    - 邮件发送：集成邮件服务，支持自定义模板（可引用事件数据）。
    - Webhook：向指定 URL 发送 POST 请求，Body 为 JSON 格式的事件数据。
    - 站内通知：通过现有通知系统发送给指定用户。

4. **执行日志与调试**
    - 每次规则触发生成一条执行记录，记录触发时间、事件数据快照、各节点状态（成功/失败/跳过）和输出。
    - 提供日志查询页面，支持按规则筛选，以时间线形式展示详细执行链路。
    - 提供调试模式：管理员可手动触发一个模拟事件，逐步执行流程，前端高亮当前节点并显示中间数据，直至流程结束。

## 验收标准
- 创建规则：当文章发布且分类为“公告”时，发送 Webhook 到 `https://example.com/hook`。发布一篇分类为“公告”的文章，该 URL 收到 POST 请求，Body 包含文章标题和链接；发布“随笔”则不触发。
- 搭建复杂规则：文章发布 → 等待 10 分钟 → 若阅读量 < 10 → 站内通知作者“文章表现不佳”。发布文章后 10 分钟，阅读量未达标时作者收到通知；达标则不通知。
- 执行日志页可看到每次触发的完整时间线，每个节点的输入输出清晰可见。
- 调试模式下，模拟触发事件，流程逐步执行，前端高亮当前节点并暂停，可查看中间数据，无误后继续，最终无异常。
